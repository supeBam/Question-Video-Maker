# 题目视频自媒体团队运营规范

本 SKILL 固化「题目视频自媒体团队」（AgentTeams）的构成、流程与规范。船长（captain）派发任务、新成员入职、以及任何成员确认协作规则时，都应加载并遵循本规范。面向用户的说明统一使用中文。

## 一、团队构成与职责

| 成员 | 角色 | 核心职责 |
|------|------|----------|
| 船长 | 协调人 | 拆解派发任务、跨角色同步信息、代跑 OpenCLI、对外汇报 |
| 内容选题 | 选题策划 | 基于对标账号与已验证爆款收集选题数据，输出选题优先级 |
| 内容创作 | 题目+文案 | 按选题产出题库 JSON 与文案改写，必须加载 skill 制作 |
| 内容审核 | 合规审核 | 按 `docs/审核基准.md` 审核文案与成片，输出 ✅/⚠️/❌ 结论，结论必须附真实证据 |
| 数据分析 | 数据复盘 | 仅分析用户导入的 Excel，分平台出复盘报告 |
| 后勤 | 架构与文件管理 | 维护目录整洁、文件分类归档、执行 `docs/项目文件保护清单.md` 防误删制度；**题目整理归档执行人**：每期出题后核对 `docs/选题归档.md` 已登记（日期/期号/JSON 文件/主题）；`docs/发布台账.md` 的发布时间**不靠用户口头告知**——由数据分析在周复盘时从用户导入的 Excel 自动提取（平台后台自带发布时间列）登记，后勤负责核对归档完整性 |

## 二、核心流水线

```
内容选题（选题方向）→ 内容创作（题目+文案）→ 内容审核（过规）
        ↑                                              ↓
数据分析（复盘迭代）← 用户发布（手动） ← Remotion 渲染 → 用户剪映加 TTS → 审核复查成片
```

- 选题依据文档：`docs/选题数据-抖音视频号.md`（对标账号、爆款规律、实时验证、优先级）
- 审核结论三级：✅ 放行 / ⚠️ 修改后放行（给出可直接替换文案）/ ❌ 不通过；**每个结论必须附真实证据**（规范条款号+原文摘录、权威出处 URL、源码行号等），拿不到证据标「存疑·需人工确认」，不得编造条款号
- 审核两轮：文案阶段（题库 JSON）→ 成片阶段（剪映加 TTS 后的 MP4/封面/字幕）；审核负责准备逐句 TTS 配音文案供用户粘贴剪映
- 发布：**用户手动发布**（抖音 + 视频号，不用 OpenCLI publish），建议 19:00 整点

## 三、内容创作规范

1. 创建/修改任何题库 JSON 前，必须先加载 `generating-quiz-json` skill 并严格遵循（含 references/quiz-data-schema.md；校验脚本实际路径为 `.agents/skills/generating-quiz-json/scripts/validate_quiz_json.py`，注意 `.agents` 为复数）。
2. 文案与选题按视角选型（用 skill 工具加载对应视角 skill）：
   - 万物雅称 fill ← `maweidu-perspective`（以物证史、通俗至上）
   - 诗人趣事 choice ← `daijianye-perspective`（拉下神坛说人话、幽默）
   - 诗句情感/情话 choice ← `yigongzi-perspective`（走心共情、翻译式降维）
   - 诗词讲读/字义考据/名句出处 ← `kangzhen-perspective`（知人论世、训诂求真、权威庄重）
   - 选题方向/标题句式/「这个动作能不能带来收益」决策 ← `huashan-perspective`（文化母体挖矿、超级符号借力、销售目的倒逼）
3. 解析（explanation/punchline）必引可考证原文出处，不得把野史写成断然事实。
4. 标题铁律：不用「99%的人」等无来源数字，改用「绝大多数人」；沿用已验证句式「美到可以当名字」「你天天说」。
5. 创作前必查重：对照 `题库记录.md` 与 `src/data/` 全部题库，同一雅称/知识点/诗句线索不得重复；新题入库后同步登记 `题库记录.md`。

## 四、内容审核规范

- 依据 `docs/审核基准.md`（微信视频号运营规范 + 抖音社区自律公约整理），结论三级、高危红线命中即 ❌。
- **证据支撑铁律**（用户要求）：违规判断必须引规范具体条款编号+原文摘录（或官方公告 URL）；事实性错误判断必须给权威出处比对；合规判断也要说明依据；拿不到证据标「存疑·需人工确认」，不得凭感觉、不得编造条款号。下结论前必须 read 磁盘当前文件，禁止使用旧快照。
- 每题/每期必查字段：题干、答案、explanation、punchline、publish.title/hashtags、outro hook、bgm 版权来源。
- 成片阶段（含 TTS）复查清单见 `docs/审核基准.md`；审核负责准备逐句 TTS 配音文案（口语化、断句、标点完整）供用户在剪映使用。
- 存量风险提示：第 1/7 期诗人私德野史题须标「据传」；第 13 期及存量标题「99%的人」类无来源数字须整改为「绝大多数人」。

## 五、数据分析规范

- 数据来源：仅用户导入的 Excel（`docs/数据分析/导入/抖音/`、`docs/数据分析/导入/视频号/`），**不得自行用浏览器或 OpenCLI 抓取平台数据**。
- 平台严格分区：抖音/视频号数据不混算；报告命名 `平台-YYYYMMDD-主题.md`，双平台对比单独成篇并标注口径。
- `docs/数据分析/原始数据/` 下的 OpenCLI 落盘文件为冻结历史基线，引用时标注「历史快照 2026-08-27，仅作参考」。
- Excel 规范：命名 `YYYYMMDD-平台-内容.xlsx`；表头第一行；日期 `YYYY-MM-DD`；注明数据截止时间。
  - 抖音必填 7 列：发布日期、作品标题/期号、播放量、点赞数、评论数、收藏数、转发数；建议补充涨粉数/完播率/5秒留存率/2秒跳出率等。
  - 视频号必填 7 列：发布日期、作品标题/期号、播放量（后台「播放次数」）、点赞数、评论数、转发数、收藏数；建议补充关注数/完播率/平均播放时长。
- **周复盘一键脚本**：运行 `node scripts/weekly-review.mjs --wechat=导入/视频号/…csv --douyin=导入/抖音/…xlsx` 完成①台账自动登记（发布时间取自 Excel，无需用户口头告知，已登记自动去重）②`out/` 调试垃圾清理（成片与未识别清单一律保留）③复盘摘要；未识别行写入 `out/ledger-unmatched-*.txt` 请用户确认，绝不猜测。只跑台账用 `build-ledger.mjs`。

## 六、文件保护制度（后勤执行）

- 权威依据：`docs/项目文件保护清单.md`（三级清单：绝对禁止删除/移动 → 需船长批准 → 可安全清理）。
- 防误删规则：任何删除/移动先列清单报船长批准，由后勤用 `git rm`/`git mv` 执行；git 可恢复 ≠ 可随意删；不确定时默认按受保护处理。
- 绝对保护对象包括：`src/data/` 全部题库、`题库记录.md`、`docs/` 全部规范与报告、`public/assets/` 全部素材、`.agents/skills/`、`.agent-teams/`、`package.json`、`README.md`、`AGENTS.md`、`.git/`。
- 文件分类与命名规范见 `docs/项目文件分类规范.md`（冲突时以保护清单为准：宁可不删，不可错删）。

## 七、工具与权限边界

- OpenCLI douyin 适配器（douyin profile/videos/stats/search/hashtag）**仅船长可运行**——成员会话执行 browser_opencli_run 会被策略拒绝；成员需要数据时由船长代跑并落盘 `docs/数据分析/原始数据/`。
- **发布由用户手动执行**：不使用 douyin publish/draft 等发布类命令；团队只交付渲染产物、TTS 文案与发布建议（19:00 整点）。
- 当前数据主来源为 Excel；OpenCLI 代跑只在用户明确要求时进行。
- 浏览器工具用于选题侧公开页面观察（如抖音热点榜 ESC 关闭登录框后提取），不得批量抓取、绕过登录墙、下载视频。

## 七、已验证的运营规律（t1/t2/t3 数据基线）

- 选题优先级：① 万物雅称第 4 期（酒/茶/棋/画/雨/扇）② 诗人趣事（冷知识 16 期）③ 「花」字网（诗词填字）。
- 主题验证：雅称类点赞率全账号最高（2.93%）、词源类播放均值最好（412）✅；情感故事类垫底（陆游 38 播放全零互动）❌ 后置。
- 爆款公式：具体事物 + 颠覆认知句式 + 19:00 整点发布（效果 2.3 倍）+ 时长 78~110 秒。
- 完播率是当前第一瓶颈（2.62%~6.09%）：第一题 5 秒内出题、15 秒内揭晓；首屏 2 秒大字单行悬念（≤10 字）。

## 九、任务派发规范（AgentTeams）

- 用 `agent_teams_create_task` 创建任务，写明 assignee；成员自行 claim，全程使用当前 attempt_id 更新状态。
- 有依赖时用 dependencies 串流水线（如：创作依赖选题完成、审核依赖创作完成）。
- 跨角色数据联动要即时同步：如数据分析的完播率结论须立刻转发给正在创作的内容创作，用于调整 timing。
- 成员汇报后船长汇总同步用户；成员就位说明中要求其先完成工具集确认与文档通读再开工。
