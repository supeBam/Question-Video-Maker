# 一键发布助手 · 使用说明（半自动：机器填表，人来点发布）

> 适用范围：本项目**答题类**与**国学对谈类**成片的日常发布（视频号 + 抖音）。
> 建立：2026-09-10。两个平台后台的表单结构、控件位置、字数与体积上限，均为本日**本机实测**取值。

---

## 一、为什么停在「只填不发」

| 全自动群发 | 本助手（半自动） |
|-----------|----------------|
| 平台风控把网页批量上传当营销号，限流甚至封号 | 每次发布仍由人在页面上核对后亲手点「发表 / 发布」 |
| AI 生成内容来不及逐条核对标识 | 自动勾上「含AI生成内容」/「内容由AI生成」，人再确认一眼 |
| 标题被截断、话题掉块了也不知道 | 填完回读一遍并把结果打印出来，异常就停下 |

省掉的体力活是**投文件 + 抄文案 + 选封面 + 勾声明**（每天 2 平台 × 2 次 ≈ 4 遍）；
保留的人工断点只有**每平台点一次发布**。

## 二、日常用法（两步）

### 第 1 步：出清单

```bash
npm run render:auto -- out/成语-第18期.mp4 \
    --data=src/data/questions-260911-1.json --video-label=成语-第18期   # 照常出片

npm run publish:prepare -- out/成语-第18期.mp4 \
    --data=src/data/questions-260911-1.json
```

产出 `out/成语-第18期-publish.json`，终端同时打印两个平台的待填文本与自检：

- `❌`（正文超限 / 体积或时长超限）→ 别去后台，先改文案重跑；脚本退出码 2。
- `⚠️`（短标题超 16 字、标题含标点、话题被 5 个封顶截断、缺封面）→ 可以继续，但要看一眼。

### 第 2 步：让助手填表

在 DSH 里说一句：

> 一键发布 out/成语-第18期.mp4，填好我去点发布

助手会走 `one-click-publish` 技能（`.agents/skills/one-click-publish/SKILL.md`），自动完成：

1. **视频号助手**：投成片 → 填视频描述（话题自动成块）→ 填短标题 → 勾「视频标注 = 含AI生成内容」→ 上传封面并确认裁剪；
2. **抖音创作者中心**：投成片 → 填作品标题 → 填简介并把话题逐个回车成块 → 「自主声明 = 内容由AI生成」→ 传竖封面并保存裁剪；
3. 填完把两边实际填入的文本回读打印，然后把页面交还给你，**由你点「发表 / 发布」**（想错开时间就在页面上选「定时 / 定时发布」）。

前提：Chrome 已开、huashu-chrome 扩展已连、两个后台都是登录态。

## 三、发布清单里有什么

`out/<期号>-publish.json`：

```
label / series / episode        期号身份（带 --data 时填）
assets.video                    路径、绝对路径、体积、时长、分辨率、fps
assets.cover                    封面（自动按命名约定配对）
assets.publishText              文案 txt 来源
platforms.wechat.fields         { "短标题": …, "视频描述": "正文 + 话题" }
platforms.douyin.fields         { "作品标题": …, "作品简介": "正文 + 话题" }
platforms.*.checks              逐条自检（ok / warn / error）
platforms.*.aiLabel             该平台 AI 声明的位置与选项文案
blocking                        所有 error 汇总（非空即不该发）
```

### 平台规则（实测，改这里：`scripts/publish/prepare.mjs` 的 `PLATFORM_LIMITS`）

| | 视频号 | 抖音 |
|---|--------|------|
| 标题 | 短标题 ≤16 字，规则建议无标点（超限只 warn） | **≤30 字硬限**，超了平台静默截断 |
| 正文 | ≤1000 字 | ≤1000 字 |
| 话题 | 写在描述里（`#词 + 空格`自动成块），无数量硬限 | 简介里 `#词` 后**必须回车**才成块，≤5 个 |
| 时长 / 体积 | ≤8 小时 / ≤20GB（建议 720p+、码率 ≤10Mbps、MP4/H.264） | ≤1 小时 / ≤16GB |
| AI 声明 | 视频标注 → 含AI生成内容 | 自主声明 → 内容由AI生成 |
| 其他默认值 | **位置会默认带本机城市**，不想露就点掉 | 只设竖封面时会自动派生横封面 |

**抖音标题超 30 字会自动切**：在句读处断开，切走的半句并进简介，一个字不丢
（清单里 `platforms.douyin.movedFromTitle` 记着切走了什么，并会打 `⚠️`）。

## 四、素材命名约定（清单自动配对封面与文案）

| 内容线 | 成片 | 封面 | 发布文案 |
|--------|------|------|---------|
| 答题 | `out/<期号>.mp4` | `out/<期号>.png` | `out/<期号>.txt` |
| 国学对谈 | `out/<期号>-成片.mp4` | `out/封面-<期号>.png` | `out/发布内容-<期号>.txt` |

对不上号时用 `--cover=` / `--text=` 手工指定。

## 五、踩过的坑（已写进技能，别重复试）

1. **`upload` 报 `atob 解码失败`**：Chrome 里跑的是旧扩展代码，调一次 huashu-chrome 的 `reload` 工具即可，不用换方案。
2. **视频号后台是「外壳 + 同源子应用 iframe」**：快照看得见的元素只是镜像，`type`/`click` 会报「被遮挡」；
   真节点在 iframe 内，必须 `eval` 进去操作。上传框也在 iframe 里，`upload` 穿不进去
   （会把文件当拖放丢到 `body`，页面不接）→ 用 `assets/relay.js` 页内中继（顶层代理 input 收 CDP 投盘，再转发进 iframe）。
3. **别想在页面里 fetch `http://127.0.0.1` 取本机文件**：Chrome 本地网络访问策略把 fetch / XHR / WebSocket / img 全部拦掉。
4. **别直连子应用 URL**（`…/micro/content/post/create`）：返回 `Cannot GET`，子应用只能由外壳挂载。
5. 抖音的「添加作品简介」框会被批量动作当成提交类控件拦下，单独 `type` 一次即可。
6. 一次性动作没带 `tabId` 会落到缺省槽（整个会话共用），多平台并行必翻车 —— 每条命令都带 `tabId`。

## 六、相关指令与文件

```bash
npm run publish:prepare -- <成片.mp4 | --latest> [--data=题库.json] [--cover=…] [--text=…] [--json]
```

- `scripts/publish/prepare.mjs` —— 清单生成（解析文案 txt、ffprobe 体检、平台字数/体积自检、抖音标题切分）
- `tests/publish-prepare.test.mjs` —— 解析与切分单测（`npm test`）
- `.agents/skills/one-click-publish/SKILL.md` —— 助手执行 SOP（两个平台的逐步操作与选择器）
- `.agents/skills/one-click-publish/assets/relay.js` —— 视频号 iframe 上传中继
- `.agents/skills/one-click-publish/assets/fill-wechat.js` —— 视频号「描述 + 短标题 + AI 标注」一次填完的页内脚本
