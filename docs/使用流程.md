# 项目使用流程

## 1. 选择数据与生产方式

先用 `examples/questions-261105-1.json` 复现 `BurstQuiz`；它混合一题选择题和一题填空题。正式创作按 `AGENTS.md` 查重和登记，新文件存 `src/data/questions-YYMMDD-序号.json`。

- 选择题：`type: "choice"`、唯一 `id`、`stem`、2–4 个 `options`、从零开始的 `answerIndex`、`explanation`。
- 填空题：`type: "fill"`、唯一 `id`、`stem`、`answer`、`explanation`；可加 `hint`。
- 同一期可混合这两种题型；完整字段以 `src/types.ts` 为准。
- `meta.series` 和 `episodeLabel` 决定默认输出及配音目录；每期使用独立值，避免覆盖其他期。
- 快闪片头用 `timing.hookSeconds`；旧字段 `introSeconds` 不控制 BurstQuiz 片头。默认存在答案回顾段，需要关闭时设 `summarySeconds: 0`。
- `background.src` 是 `public/` 下的相对路径，如 `assets/example-paper.svg`；不是文件系统绝对路径。

修改示例时保留完整的 `meta`、`timing`、`intro`、`outro`、`voiceOver`、`bgm` 和 `questions`。`answerIndex: 1` 表示第二个选项；填空题答案写在 `answer`。

## 2. 安装并预览

```bash
npm ci
npm test
npx tsc --noEmit
npm run dev:data -- --data=examples/questions-261105-1.json
```

Studio 选择 `BurstQuiz`，检查中文字体、题干、选项、答案和节奏。所有命令均在仓库根目录执行。`npm run dev` 使用默认数据；预览指定数据时使用 `dev:data`。

## 3. 无 API 出片与手工配音

```bash
npm run render:manual -- out/入门示例-第01期.mp4   --data=examples/questions-261105-1.json
```

生成 MP4、PNG、SRT、TXT。配音强制关闭，BGM/音效仍由数据控制；示例已经同时关闭音频。可将 MP4 和 SRT 导入剪辑软件手工配音，再导出最终成片。

只生成字幕和文案，可跳过浏览器渲染：

```bash
npm run render:manual -- out/入门示例-第01期.mp4   --data=examples/questions-261105-1.json --srt-only
```

该命令不生成视频或封面，不能单独作为出片成功的依据。渲染共用 `out/.remotion-props.json` 临时文件，同一工作区按顺序执行多个渲染任务。

## 4. 可选：自动 TTS

此步骤会向 MiniMax 发送配音文本并消耗账户额度。先确定用户授权的文本、音色及调用范围，再执行。只做预览或手工配音时跳过本节。

macOS / Linux 下准备：

```bash
python3 -m venv .venv-asr
.venv-asr/bin/python -m pip install requests
ffmpeg -version
ffprobe -version
```

`ffmpeg` 与 `ffprobe` 需自行安装并加入 PATH；只做 TTS 无需安装 FunASR。自动包装脚本当前固定使用 `.venv-asr/bin/python`，Windows 用户可先使用 WSL，或选择手工配音流程。

在项目根目录通过本机编辑器创建 `.minimax.key`，仅写一行有效密钥。它受 `.gitignore` 保护；不要将真实密钥写进聊天、题库或文档。可用 `git check-ignore .minimax.key` 验证忽略规则。

```bash
npm run render:auto -- out/入门示例-第01期.mp4   --data=examples/questions-261105-1.json   --video-label=入门示例-第01期
```

输入示例的静音配置会被自动模式覆盖为启用口播。脚本先生成音频，再通过 ffprobe 实测时长，最后渲染带配音视频、封面和发布文案；自动模式默认不生成 SRT。主要中间产物：

- `public/assets/tts/{series}-{episodeLabel}/`：逐题音频，属于本地生成文件。
- `src/data/.tts-cache/`：增量合成缓存，文本或音色变化会重新合成。
- `out/{video-label}-audio-measurements.json`：实测时长。

按需用 `--tts-arg=--voice-stem=音色ID` 传入脚本支持的参数；以 `gen-burst-tts.py --help` 为准。题库可写 `tts.textOverrides` 修正朗读文本，先检查多音字，再检查是否有截断或重叠。

## 5. 可选：ScrollShow 画卷展示

数据示例是 `src/data/scroll-show-260911-1.json`，结构见 `src/ScrollShow.tsx` 的 `ScrollShowData`。它使用 `items[]` 而不是 `questions[]`。

该组件会读取每条 `item-{id}.mp3`，因此先合成或提供与 `tts.audioDir` 对应的音频，再预览 / 渲染。历史数据可能引用未随仓库提供的本地媒体，运行前先核对其所有资源路径，并替换为自己有权使用的文件。不要将这条产线当作无音频快速示例。

配置好第 4 节依赖和密钥后，可运行：

```bash
npm run render:auto -- out/万物雅称-第01期.mp4   --composition=ScrollShow   --data=src/data/scroll-show-260911-1.json   --video-label=万物雅称-第01期
```

输出视频、封面和文案；展示流不走题库的 SRT 生成器。

## 6. 验收与准备发布

用播放器查看 MP4，重点查看开头、选择题揭晓、填空题揭晓和片尾；打开 PNG 看清晰度和文字裁切；核对 SRT 与 TXT。自动配音需实际试听，不以“进程退出码 0”代替视听检查。

需要发布清单时安装 `ffprobe` 后运行：

```bash
npm run publish:prepare -- out/入门示例-第01期.mp4   --data=examples/questions-261105-1.json
```

输出同目录的 `入门示例-第01期-publish.json`，包含本机素材绝对路径和平台字段。它用于本地操作，不提交到仓库；检查其中的 blocking 项并按真实平台规则复核。该命令只准备清单，不上传、不发布。

## 常见问题

| 现象 | 处理 |
|---|---|
| Node 报不支持 `.ts` 导入 | 使用 Node 22.18+；本项目渲染脚本直接导入 TypeScript |
| 浏览器无法下载 / 启动 | 检查网络与 Remotion 浏览器安装日志；容器补齐 Chromium 系统依赖 |
| 中文方框或字形不一致 | 安装中文字体，检查 `src/theme.ts` 字体栈，再重新预览 |
| 资源 404 | 将 `assets/x` 对应到 `public/assets/x`；历史媒体不一定随仓库提供 |
| 缺 BGM / 音效 | 换为有授权的文件，或分别关闭 `bgm.enabled` 与 `timing.soundEffects` |
| 缺 `.venv-asr/bin/python` | 先创建第 4 节虚拟环境，或改用 `render:manual` |
| API 失败 | 检查服务账号、额度与脚本返回码，保存任务状态后再决定是否重试 |
| 字幕时间或口播长度不符 | 确认使用同一份数据及对应 measurements，检查是否拿错期号 |
| 误覆盖已有产物 | 给每期独立输出名；当前 Remotion 配置允许覆盖同名文件 |
