## 二、登记规则

1. **每发一条视频登记一行**；同一期双平台发布则登记两行（对应同一个 JSON 文件）。
2. 「发布日期 / 时间」**一律取自用户周复盘导入的 Excel**（平台后台导出的实际发布时间，与 Excel 口径天然一致），无需用户另行告知；个别平台 Excel 无时间列时留空或标「—」。
3. 「实际发布标题」填平台后台**显示的标题**（Excel 中的原标题列）；若做过合规整改（如「99% 的人」→「绝大多数人」），以整改后的标题为准。
4. 找不到 JSON 文件的期次，JSON 文件列填「？（待补）」，并通知船长补 `选题归档.md`。

---

## 三、周复盘对应流程（数据分析执行）

1. 读用户导入的 Excel（`docs/数据分析/导入/{抖音,视频号}/`，按平台分区）。
2. 对每一行，按「发布日期 + 实际标题」查本台账 → 得到**期号** → 查 `docs/选题归档.md` → 定位 `src/data/questions-*.json`。
3. 输出「每条视频 ↔ 对应题目」对照表（平台 / 期号 / JSON 文件 / 题型 / 题量 / 主题），再按现有报告格式做题型 × 平台矩阵分析。
4. **识别优先级**：① 标题中的栏目 / 期号关键词（如「万物雅称第2期」）；② 标题片段 + 「发布日 ≥ 剪片日（JSON 文件名日期）」软校验；③ 两者都不行 → 列入「未识别清单」**请用户确认，绝不猜测**；确认后补登本台账。
5. 台账为空或缺失时，允许以 `选题归档.md` + 标题关键词临时识别，但复盘报告须标注「未入台账」并补登。

## 四、与 `选题归档.md` 的分工

| 文档 | 记录侧 | 登记时机 |
|---|---|---|
| `docs/选题归档.md` | 出题侧：哪天出了哪期、哪个 JSON 文件、什么主题 | 出题 / 审核时 |
| `docs/发布台账.md`（本文件） | 发布侧：哪条视频何时在哪个平台发布、实际标题 | 发布后（或周复盘时补登） |

- 周复盘以 **本台账 + 用户 Excel** 为数据准绳；`选题归档.md` 仅用于「期号 → JSON 文件」定位。
- 出片 / 发布建议统一命名与标题带期号（如 `out/万物雅称-第02期.mp4`、标题「万物雅称第2期｜…」），让平台标题天然含期号，对应全自动。
