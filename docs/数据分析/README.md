```

│   ├── 抖音/
│   │   ├── 单条视频/   ← 一条视频一行（抖音-20260903-单条视频-20260806~20260902.xlsx）
│   │   └── 每日汇总/   ← 一天一行（抖音-20260903-每日汇总-20260806~20260902.xlsx）
│   └── 视频号/
│       ├── 单条视频/   ← 一条视频一行（视频号-20260903-单条视频-20260806~20260902.csv）

└── _归档/              ← 历史文件统一归档区（旧导入数据 + 历史文档产出），只读不分析
```

## 例行节奏（2026-09-03 起）

- **每周一 09:00** 用户导出 4 个文件（两平台 × 单条视频/每日汇总），窗口 = 上周日往前 30 天；导出后按规范命名放入对应目录，随后做周复盘。
- **每月第一个周一** 加做月度复盘，打通题库台账做「选题 × 表现」归因。
- **合并规则**：同一条视频出现多份快照时，取导出日最新的那份（文件名里的导出日判定）。
- **防丢规则**：窗口起点固定为「上周日往前 30 天」，不用「近 7 天」滚动窗口，否则老视频会随窗口前移掉出快照链。
- **数据看板（2026-09-03 起）**：`看板.html` 为展示层入口，随周复盘更新——导出 4 文件后运行
  `python3 scripts/analytics/extract-dashboard-data.py` 生成 `看板-data.json`，在看板中「导入新数据」即可；用法见 [`看板-说明.md`](看板-说明.md)。看板不替代周复盘报告。

## 工作模式原则（2026-08-27 起生效）

1. **唯一数据来源 = 用户导入的 Excel**：数据分析只分析 `导入/` 下的用户表格，
   **不自行抓取数据**（停用浏览器与 OpenCLI；不再请求船长代跑 opencli douyin 命令）。
2. **历史文件只读不分析**：`_归档/` 下的旧导入数据与历史文档仅作回溯参考，**不作为当期分析依据**；
   当期分析一律以 `导入/` 活跃目录 + `分析报告/` 最新基线为准。
3. **抖音 / 视频号严格分区**：
   - 导入按平台分子目录存放（`导入/抖音/`、`导入/视频号/`）；
   - 两平台数据**不得混算**：均值、基线、比率分别计算；
   - 需要跨平台对比时，单独成篇并在文中明确标注两平台口径差异。

## Excel 导入规范

- **存放位置**：直接把平台原始导出文件放进 `docs/数据分析/导入/`（根目录或任意子目录均可，**名字随意，无需手动改名**）——AI 用 `python3 scripts/analytics/extract-dashboard-data.py --organize` 自动识别平台/颗粒度、改名并归位到 `导入/{平台}/{颗粒度}/` 子目录（识别依据：文件名关键词优先，表头内容兜底）。
- **命名规范**（落盘结果，由 organize 自动生成）：`平台-导出日-颗粒度-数据窗口.ext`，如 `抖音-20260903-单条视频-20260804~20260903.csv`。
  「导出日」= 文件导入时间（mtime；若早于数据截止日按数据截止日取）；「数据窗口」= 从文件日期列自动提取。
- **表头要求**：见下文「两平台最小字段要求」；表头行在第一行，日期统一 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM`。
- **转换流程**：Excel（xlsx）为二进制，`scripts/analytics/extract-dashboard-data.py` 已内置纯标准库 xlsx 读取（零第三方依赖），日期列需以文本存储；视频号 CSV 直读（注意编码 utf-8-sig）。清洗规则：视频号「平均播放时长」自动去「秒」字解析；播放为 0 的作品留存字段归零；每日汇总负互动归零。
- **口径提示**：请在表格中注明数据截止日期（如「数据截至 2026-08-27 12:00」），避免口径漂移。
- **Excel ↔ 题库对应**：单条作品的「发布日期 + 标题」按 [`docs/发布台账.md`](../发布台账.md) 识别为**期号**，再经 [`docs/选题归档.md`](../选题归档.md) 定位到 `src/data/questions-*.json`，即可取到该条视频对应的题目（题型/题量/主题）。台账查不到的行列入「未识别清单」请用户确认，不猜测。

## 周复盘一键脚本（推荐）

把台账整理 + out/ 清理 + 复盘摘要串成一条命令（数据分析执行）：

```powershell
node scripts/analytics/weekly-review.mjs --wechat=导入/视频号/…csv --douyin=导入/抖音/…xlsx
```

- 自动完成：① Excel/CSV → 期号识别 → 更新 [`docs/发布台账.md`](../发布台账.md)（已登记自动去重）；② 清理 `out/` 调试垃圾（仅删可再生的预览/检查截图与 props 残留，**成片与未识别清单一律保留**）；③ 输出本周复盘摘要。
- 抖音 xlsx 自动调用本机 Excel COM 转 CSV（兼容 Excel 2007 的 ANSI 格式）；视频号 CSV 直读。
- 可选参数：`--no-clean` 跳过清理；`--out=…` 指定台账路径；多个同平台文件用逗号分隔。
- 只跑台账不动 out/：`node scripts/analytics/build-ledger.mjs --wechat=… --douyin=…`。

### 两平台 Excel 最小字段要求

**抖音 · 单条视频（必填字段）**：

| 字段 | 说明 |
|---|---|
| 发布日期 | 作品发布时间 `YYYY-MM-DD HH:MM`（至少到日期） |
| 作品标题/期号 | 填平台后台**原标题**即可；数据分析按发布台账识别期号（如「万物雅称第3期」） |
| 播放量 | 单条播放次数 |
| 点赞数 | 单条点赞 |
| 评论数 | 单条评论 |
| 收藏数 | 单条收藏 |
| 转发数 | 单条转发（分享） |

建议补充（有则更佳）：涨粉数、完播率、5 秒留存率、2 秒跳出率、平均播放时长、粉丝观看占比、主页访问量。

**抖音 · 账号概览表（建议随附）**：统计日期、粉丝数、关注数、获赞总量、作品总数。

**视频号 · 单条视频（必填字段）**：

| 字段 | 说明（视频号后台口径） |
|---|---|
| 发布日期 | 作品发布时间 |
| 作品标题/期号 | 填平台后台**原标题**即可；与抖音同源内容对应（同一条目对应同一 JSON 题库） |
| 播放量 | 视频号后台「播放次数」 |
| 点赞数 | 点赞（红心） |
| 评论数 | 评论 |
| 转发数 | 转发 |
| 收藏数 | 收藏 |

建议补充：关注数（单条涨粉）、完播率、平均播放时长、分享人数。

**视频号 · 账号概览表（建议随附）**：统计日期、粉丝数、关注数（账号关注他人数）、作品总数。

## 分析报告命名规范

- 报告存放 `分析报告/`，文件名用**平台前缀**：`平台-YYYYMMDD-主题.md`；
  - 示例：`抖音-20260827-周复盘.md`、`视频号-20260827-周复盘.md`
- 双平台对比单独成篇，命名 `对比-YYYYMMDD-主题.md`，文中明确两平台口径差异；
- 每期报告包含：数据来源（Excel 文件名 + 截止日期）、关键数字、逐维度分析、
  结论与建议（标注「事实/推测」）、待补数据（仅限「请用户下次导表补充」，不再请求 OpenCLI 代跑）。

## 数据口径约定

- 平台字段按原始表字段名引用，不擅自改名；单位（万/亿）在报告中标明。
- 分析结论需区分「事实」（数据可见）与「推测」（需更多数据验证）。
- 引用 `_归档/` 历史文件时，必须标注「历史快照」及日期，仅作参考、不作当期基线。
- 外部行业基准引用必须带来源链接。
- **视频号发布时间回填**（2026-09-03 起）：视频号 CSV 只有「发布日期」无「发布时间」列，而同一视频两平台同一时间发布（用户已确认）。登记台账时，视频号的「发布时间」用抖音 xlsx 同日期同内容的发布时间回填；抖音未发的视频号独发内容留「—」。
- **台账去重局限**：台账 dedup key = `日期|平台|期号`，同一天同平台同期号若发多条视频会被合并为一条。遇到这种情况（如抖音 08-30 代称 06:00 与 18:00 两条）需人工确认并分别登记。
- **JSON 文件名日期 ≠ 发布日期**（2026-09-03 起）：JSON 文件名的 YYMMDD 是**剪片/建题库日**（用户提前剪好视频），发布日期是**定时发布日**，通常比剪片日晚 0~1 天。期号识别只作「发布日 ≥ 剪片日」软校验，不作「发布日期 ≈ JSON 日期」硬判定。
