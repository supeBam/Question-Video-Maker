## 零、先说结论：现有报告为什么"不够深入"

诊断对象：`分析报告/视频号-20260831-周复盘.md`、`分析报告/抖音-20260831-周复盘.md`、`分析报告/20260827-核心指标分析框架.md`、`scripts/weekly-review.mjs`。

现有报告的质量其实不差——数据准确、口径有交代、事实与推测有区分。问题不在"写得不用心"，而在**报告形态停在描述层**：完整地回答了"发生了什么"，但基本没有回答"所以该做什么、做了会怎样"。具体是六个结构性缺陷：

| # | 症结 | 现报中的实例 | 后果 |
|---|---|---|---|
| 1 | **成熟度混排** | 16 期用发布首日 1,680 播放，与 4 句话的周累计 1,477 同榜排名 | 排行榜失真，"起量速度第一"实为不可验证结论（历史作品缺 D1 快照） |
| 2 | **小样本下结论** | 词源 n=3、雅称 n=3，即判"雅称在视频号垫底" | 置换检验双尾 **p=0.20**（脚本实测），远超 0.05，却被写成既定事实 |
| 3 | **只有环比，没有分解** | 播放 +47.2% 之后直接给题材结论 | 无法回答"该多发一条还是该把单条做好"——这是排期决策的核心 |
| 4 | **没有目标，只有环比** | 全篇无目标值、无达标判断 | 无法回答"本周做没做到"，+47% 可能其实是未达标 |
| 5 | **归因无对照** | "16 期节奏改革见效" | 该条同时换了节奏、又是词源题材、又赶上全周最高播放日，三因素混淆，n=1 |
| 6 | **建议不带数字** | "继续加码词源冷知识" | 无预期影响、无验证指标、无回收时点，建议发出即失联，无法验证对错 |

**根因一句话**：报告以"数据"为起点组织（有哪些数就写哪些），而不是以"决策"为起点组织（下周要拍板什么，缺什么证据就补什么）。

本体系的所有改动，都是把这六个缺陷逐一关掉。

## 一、设计原则

1. **决策优先**：每份报告开头必须写明"本报告服务于哪个决策"。没有决策对象的分析不写。
2. **口径先于数据**：成熟度、平台、快照时点三个维度不统一，数字不许进结论。
3. **不确定性显式化**：每条结论强制标注 `样本量 n` + `置信度（高/中/低）` + `结论级别（观察/假设/结论）`。宁可说"证据不足"，也不把猜测写成事实。
4. **建议三件套**：每条建议必须带 **预期影响区间** + **验证指标** + **回收日期**，否则不写进报告。
5. **闭环而非归档**：建议进决策台账，到期必回收，验证/证伪都要记录。
6. **自动化描述，人工做判断**：描述性统计交给脚本（见 `scripts/analytics/deep-metrics.mjs`），分析师的产能全部投到归因与决策。

## 二、三层报告体系

```
┌─────────────────────────────────────────────────────────┐
│ 第三层  洞察层  【月度 / 季度】                            │
│ 专题深度分析 · 季度战略复盘                                │
│ 回答：哪类内容值得做成系列？账号定位要不要调？              │
│ 方法：分批实验、对照设计、小样本检验、基线建模              │
├─────────────────────────────────────────────────────────┤
│ 第二层  决策层  【每周一】                                  │
│ 周复盘（裁决型）                                           │
│ 回答：达标了吗？变化谁驱动？下周排什么？上期决策验了吗？     │
├─────────────────────────────────────────────────────────┤
│ 第一层  监测层  【数据导入即跑，自动】                      │
│ 数据质量门禁 + 异常告警                                    │
│ 回答：数据能不能用？有没有东西坏了？                        │
│ 只报异常，不做分析、不给建议                                │
└─────────────────────────────────────────────────────────┘
```

### 2.1 第一层 · 监测层（自动，不做分析）

- **触发**：用户导入 Excel/CSV 后，随 `weekly-review.mjs` 自动执行。
- **产出**：DQ 门禁评分（见 `02-数据质量门禁.md`）+ 告警清单。
- **纪律**：本层**禁止**出现归因与建议。它的唯一职责是"把坏数据和不正常的现象挑出来"。
- **告警项（初期 4 条，后续按 `01-指标字典.md` 阈值扩展）**：
  1. 单条播放低于同成熟度基线 50%；
  2. 点赞率低于账号基线 30%；
  3. 完播率连续 3 期下滑；
  4. 存量标题 8 条异常追踪（沿用 D8 维度）。

### 2.2 第二层 · 决策层（周复盘，周一）

周复盘从"叙述体"改为"裁决体"。固定回答 4 个决策问题，篇幅压缩 40%，信息密度提高：

| 决策问题 | 方法 | 输出 |
|---|---|---|
| Q1 本周达标了吗？ | 目标 vs 实际 + pacing | 达标 / 未达标 / 超额，及缺口归因到指标 |
| Q2 变化由什么驱动？ | 增长分解（量/效/mix）+ 同熟度对比 | "增量的 X% 来自单条效率，Y% 来自发布条数" |
| Q3 下周排什么？ | 选题评分卡 + 平台适配矩阵 | 下周 N 条的「题材 × 题型 × 平台 × 预期 D7 播放」分配表 |
| Q4 上期决策验了吗？ | 决策台账回收 | 逐条：验证 / 证伪 / 证据不足，及沉淀结论 |

**硬要求**：正文中每一条结论后面必须跟 `（n=?, 置信度：高/中/低）`；每一条建议必须带 `预期影响 / 验证指标 / 回收日期`。

### 2.3 第三层 · 洞察层（月度专题 + 季度战略）

- **月度专题**（每次 1 个主题，轮流排期）：题材表现、标题句式、节奏时长、发布时段、平台差异、钩子结构、涨粉转化。
- **准入门槛**：专题分析必须采用 `03-分析方法库.md` 中的对照/实验设计，**不接受单期横截面描述**冒充专题结论。
- **季度战略复盘**：账号定位校准、内容资产盘点（哪些期具有长尾复利）、选题库健康度、双平台资源分配比例。

## 三、决策映射表（体系的骨架）

这是本体系最重要的一张表：把所有分析动作挂到具体决策上。**未出现在本表中的分析，一律不做。**

| 决策 | 决策频率 | 决策人 | 支撑报告 | 关键指标 | 决策输出物 |
|---|---|---|---|---|---|
| 下周出哪几期、什么题材 | 每周 | 用户（船长） | 周复盘 Q3 | 题材 D7 播放中位数、完播率、转发率 | 下周排期表（题材×平台×数量） |
| 某题材是否继续/停做 | 每月 | 用户 | 专题：题材表现 | 同题材 n≥8 的分批实验差异 + CI | 续做 / 缩减 / 停做 |
| 标题句式用哪种 | 每月 | 用户 | 专题：标题句式 | 同题材配对下 3 秒留存、点赞率差异 | 标题句式规范（进 `审核基准.md`） |
| 视频节奏/时长怎么定 | 每季 | 用户 | 专题：节奏时长 | 完播率、均播时长、答题揭晓前留存 | `questions.json` timing 默认值 |
| 双平台资源怎么分 | 每季 | 用户 | 专题：平台差异 | 平台 × 题材交互效应 | 各平台主推题材与排期占比 |
| 是否加更（提升发布密度） | 每月 | 用户 | 周复盘 Q2 增长分解 | 规模效应 vs 效率效应占比 | 加更 / 提质量 / 都不动 |
| 存量标题是否整改 | 事件驱动 | 用户 | 监测层 D8 追踪 | 环比异常、限流/下架迹象 | 整改 / 维持现状 |
| 是否投入新内容形态 | 每季 | 用户 | 季度战略复盘 | 新形态 D7 播放 vs 基线的 CI 下界 | 立项 / 观察 / 放弃 |

## 五、本体系带来的三项新增基础设施

### 5.1 D1/D3/D7 快照表（新增，最高优先级）

**这是解决"成熟度混排"的钥匙，也是全套体系里唯一需要用户配合的增量工作。**

- 位置：`docs/数据分析/原始数据/快照/YYYYMMDD-平台-明细.csv`（沿用现有导入格式，不改字段）
- 做法：同一批作品，在发布后 **第 1 天、第 3 天、第 7 天** 各导出一次明细表，文件名带快照日期。
- 用途：
  - 同熟度排行（D1 榜与 D1 榜比，D7 榜与 D7 榜比）；
  - 计算 **长尾系数 = D7 ÷ D1**，得到"这条内容能不能滚雪球"；
  - 新片发布 1 天后即可预测 D7 表现，把决策提前 6 天。
- 最低要求：**至少保证每条作品有一份 D7 快照**。在 D7 快照覆盖不足前，所有单条对比必须标注"成熟度未标准化"。

### 5.2 分析脚本（新增）

`scripts/analytics/deep-metrics.mjs` —— 把描述性统计自动化：
- DQ 门禁 12 项检查；
- 成熟度计算与同熟度分组；
- 增长分解（规模效应 / 效率效应 / 结构效应）；
- Bootstrap 分组差异与置信区间（解决小样本问题）。
输出 Markdown 片段，直接粘进周复盘。用法见 `03-分析方法库.md` 第六节。

### 5.3 决策台账（新增）

`06-决策台账.md` —— 建议发出后不再失联。所有建议进台账，带回收日期，到期必验。这是"支持业务决策"的最后一公里。

## 六、落地路线（4 周，不搞大爆炸）

| 周次 | 动作 | 验收标准 |
|---|---|---|
| W1 | 建 D1/D3/D7 快照采集习惯 + 跑通 DQ 门禁 | 本周新发作品有 D1 与 D7 两份快照；周复盘出现门禁评分 |
| W2 | 周复盘改裁决体（4 个决策问题 + 增长分解 + 建议三件套） | 新一期周复盘按 `04-模板-周复盘.md` 产出 |
| W3 | 建决策台账并回收第一批建议 | 台账 ≥5 条，回收率 100% |
| W4 | 第一个月度专题（建议做"题材表现"，因它存量数据最多） | 按 `05-模板-专题深度分析.md` 产出，含对照设计与 CI |

**过渡期纪律（W1–W4）**：老报告格式不废弃，但新报告必须在老结构之上叠加本体系要求。不做推翻重来，避免断档。

## 八、待用户确认的三件事

1. **D1/D3/D7 三次导表是否可行？** 若太重，降级方案：只保 D7 + 发布后 24 小时内补一次 D1（长尾系数是全套体系性价比最高的一项）。
2. **周目标由谁定？** Q1"达标判断"需要目标值。建议第一版由用户提供周播放与周涨粉目标，跑 4 周后改为基线预测自动给目标。
3. **视频号账号概览表能否补上？** 目前无法计算视频号涨粉率与粉丝渗透率，DQ 门禁会把它判为阻断级（连续 3 周未补）。如确实无法导出，需在 `02-数据质量门禁.md` 中降级为警告并接受该指标永久缺失。
