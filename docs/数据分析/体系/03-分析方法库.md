## 方法零、什么时候用哪个方法

| 你要回答的问题 | 用哪个方法 |
|---|---|
| 播放涨了/跌了，是怎么回事？ | ① 增长分解（**先做批次独立性检查**，见 ① 适用前提） |
| 两期快照重叠、分解做不了？ | ① 前提检查 → 改用 **②补充 播放集中度** |
| 这批作品哪条最好？ | ② 同熟度对比 |
| A 题材是不是真的比 B 题材好？ | ③ 小样本推断 |
| 改了节奏之后变好了，是节奏的功劳吗？ | ④ 混淆控制与准实验 |
| 同一条内容在两个平台哪个更好？ | ④ 配对设计（跨平台，见 07 实战） |
| 下周这条新片能跑多少？ | ⑤ 基线建模与预测 |
| 建议写完了，然后呢？ | ⑥ 决策量化 |
| 内容发布后还能涨多久？该"等长尾"吗？ | **⑦ 内容生命周期追踪** |

## 方法一、增长分解（量 / 效 / 结构）

### 用途
把指标的变化拆成"因为多发了几条"和"因为单条变强了"。**这是"要不要加更"这个决策的唯一直接证据。**

### 公式

设基期发布 n₀ 条、单条均值 a₀；本期 n₁ 条、单条均值 a₁，总指标 T = n × a。

```
规模效应 = (n₁ − n₀) × a₀        # 多发/少发带来的
效率效应 = n₀ × (a₁ − a₀)        # 单条变强/变弱带来的
交叉效应 = (n₁ − n₀) × (a₁ − a₀) # 两者叠加部分
总变化   = 规模 + 效率 + 交叉
```

### 实例：08-31 视频号周复盘的播放增长

原文只写了「播放合计 7,071，上期 4,803，**+47.2%**」，读者无法判断该加更还是该提质量。分解后：

| 项 | 计算 | 数值 | 占增量 |
|---|---|---|---|
| 基期 | 7 条 × 686.1 | 4,803 | — |
| 本期 | 8 条 × 883.9 | 7,071 | — |
| 总增量 | — | **+2,268** | 100% |
| 规模效应 | (8−7) × 686.1 | +686 | **30.2%** |
| 效率效应 | 7 × (883.9−686.1) | +1,385 | **61.0%** |
| 交叉效应 | 1 × 197.8 | +198 | **8.7%** |

**结论（这才是可决策的）**：本周播放增长的 **约 70% 来自单条效率提升**（效率 61.0% + 交叉 8.7%），只有 30% 来自多发的那一条。因此下周的优先级是 **提升单条内容质量，而不是继续加更**；若要加更，需先确认单条效率不下滑。

> 补充提醒：本期均值 883.9 被 16 期首日值拉高，且 16 期尚未跑满 7 天，效率效应存在**高估风险**。快照体系补齐后需重算。这正是成熟度标准化的必要性。

### ⚠️ 适用前提：批次独立性检查（2026-09-02 补充，重要）

**增长分解只在"两期是两个独立发布批次"时成立。** 若两次快照的作品高度重叠，分解会失效——同一条内容被计了两次，"规模 vs 效率"的拆分不再有含义。

**执行前必做检查**（已由 `deep-metrics.mjs` 自动输出）：

```
重叠率 = 上期作品中与本期同标题的比例
重叠率 ≥ 50%  →  分解结果作废，改用「方法二·播放集中度」替代
```

**实战教训**（2026-09-02）：用 08-28 与 08-29 两份快照做分解，视频号重叠 **87.5%**、抖音 **77.8%**——因为平台导出的是"最近 N 条作品"而非"本周发布批次"。脚本给出"效率贡献 100%"，但该数字**不可用**。

> **这直接导致上一版结论「增量 70% 来自单条效率 → 应提质量」被降为观察级。** 该结论的原始计算（08-31 周复盘）同样建立在快照对比之上，需在获得真正独立的发布批次后重验。

**替代方案**：批次重叠时，用「播放集中度」回答"该加更还是提质量"（见方法二补充）。

### 方法二补充、播放集中度（分解失效时的替代品）

当两期快照重叠、无法做增长分解时，用**单条播放的离散程度**判断增长该靠什么：

| 指标 | 算法 | 判据 |
|---|---|---|
| 变异系数 CV | 标准差 ÷ 均值 | <0.4 均匀 / 0.4–0.7 中等 / >0.7 高度集中 |
| Top2 占比 | 前 25% 作品的播放占比 | 辅助验证集中度 |

| CV 区间 | 含义 | 决策 |
|---|---|---|
| **< 0.4（均匀）** | 单条产出稳定，爆款少 | **加更**：播放随条数线性累积 |
| **0.4–0.7（中等）** | 爆款与基本盘并存 | **保基本盘 + 20% 产能试爆款** |
| **> 0.7（高度集中）** | 少数爆款贡献大部分播放 | **提质量/复刻爆款**，加更边际收益低 |

**实例（2026-08-29 快照）**：视频号 CV=0.50（中等，Top2 占 44.6%）→ 保基本盘+试爆款；抖音 CV=0.26（均匀，Top2 占 35.1%）→ **可加更**。存量期 31 条 CV=1.01（高度集中，含大量失败实验）。

> 价值：这个指标**不依赖两期数据可比**，单期即可算，特别适合当前快照体系尚未建立的过渡期。

## 方法二、同熟度对比法

### 用途
消除"跑了 1 天"和"跑了 7 天"混排造成的排行失真。

### 规则
1. 每条作品先算成熟度 M，归入 D1 / D3 / D7 桶；
2. **排行只在桶内进行**，D1 榜、D3 榜、D7 榜分列；
3. 跨桶只允许比较两个无量纲量：**长尾系数 K = D7 ÷ D1**、**相对基线倍数 R = 单条 D7 ÷ 账号 D7 基线中位数**；
4. 成熟度未知 → 排除出排行，进待补清单。

### 实例：修正 08-31 周复盘的 Top 榜

原文把 16 期（D1，1,680）排在 4 句话（D7，1,477）之上，并称"起量速度全账号最快"。修正后：

| 榜 | 排名 | 说明 |
|---|---|---|
| **D7 榜**（可比） | 🥇 4 句话 1,477 🥈 皇帝改名 902 🥉 连中三元 663 | 16 期**不进榜**（M=0，发布当日） |

**实测补充**（`deep-metrics.mjs` 以 2026-08-29 为快照日跑本期 8 条）：成熟度分布为 **D0 1 条 / D1 4 条 / D3 3 条 / D7 0 条**——**本期没有任何一条作品达到 D7**，也就是说本周复盘的整张单条排行，实际上全部建立在未满 7 天的未成熟数据上。这不是报告写得不好，而是快照机制缺失导致的硬约束。
| **D1 榜**（不可比） | 仅 16 期 1,680 | 历史作品无 D1 快照，**无法比较** |

**修正后的正确表述**：「16 期 D1 播放 1,680，高于本期 D7 榜第一名（1,477）——但这不构成"起量速度第一"的证据，因为没有任何历史作品的 D1 值可供对照。**该结论当前不可验证**，待快照体系建立后重测。原报告结论应予撤回。」

> 这一条是整个体系里最"扎心"也最有价值的一条：它把一个看似亮眼的结论降级为不可验证。宁可少一个结论，不要一个错的结论。

## 方法三、小样本推断（置换检验 + Bootstrap）

### 用途
本账号每周单平台仅 6–8 条、单题材常只有 2–4 条。**在这个样本量下，t 检验和"看起来差很多"都不可靠**，必须用精确检验，并且必须报告区间而不是单点。

### 规则
- 两组比较：**置换检验（Permutation Test）**，样本全分离时的最小 p 值受组合数限制（n₁=3、n₂=3 时双尾最小 p = 0.10）；
- 单组估计：**Bootstrap 95% 置信区间**（重抽样 ≥ 2000 次），报告中给出区间；
- **p 值不达标 ≠ 没有差异**，而是"证据不足"。写"观察级"，进观察队列，不写"无差异"。

### 实例：题材对比（08-31 视频号数据）

| 组 | n | 完播率 |
|---|---|---|
| 词源冷知识 | 3 | 34.23%、31.53%、28.20%（16 期为 D1 值） |
| 万物雅称 | 3 | 18.37%、14.08%、14.07% |

原文结论：「雅称类在视频号依旧垫底」。做检验后：

- 两组全分离（词源最小值 28.20% > 雅称最大值 18.37%）；
- 置换检验（n₁=3、n₂=3，共 C(6,3)=20 种分法，统计量取中位数之差）：**双尾 p = 0.20**（`deep-metrics.mjs` 实测，非估算）；
- 若按成熟度纪律剔除 16 期（D1 值不可比），词源降为 n=2，此时 **双尾 p = 0.10**（C(5,2)=10 种分法中仅 1 种达到同等差异）。
  > 注：剔除样本后 p 值反而变小，是因为偶数样本的中位数取中间两数均值，使极端分法更难复现同等差异——**这是小样本统计的不稳定性本身，不是"剔除后证据更强"**。

**修正后的正确表述**：
「词源类完播率高于雅称类（两组全分离，中位数差 **17.45pp**；置换检验双尾 **p = 0.20**，剔除成熟度不一致样本后 n=2+3 时 **p = 0.10**，**均未达显著**）。
→ **结论级别：观察（n=3+3）｜置信度：低**。
→ 处置：进入分批观察队列，**累计至各 n ≥ 8 后再定论**；在此之前，排期可倾向词源，但不得据此确立"雅称不适合视频号"的规范。」

> 关键心态转变：**"证据不足"不等于"没有差异"**。这两者都会影响动作：前者是"继续观察、暂不写规范"，后者是"确认无差异、停止投入"。写错方向会导致过早放弃一个可能有效的题材。

## 方法四、混淆控制与准实验设计

### 用途
"改了 X 之后变好了"是最常见的错误因果。本方法把归因从"事后解释"变成"事前设计"。

### 三类设计（按可行性排序）

| 设计 | 做法 | 需要的样本 | 能回答什么 |
|---|---|---|---|
| **单变量轮换**（首选） | 固定其他变量，一次只改一个因素 | 每臂 ≥ 6 条 | "节奏变快"单独的效果 |
| **配对设计** | 同题材做两版（A/B 标题、A/B 节奏），同期发布 | ≥ 6 对 | 标题句式的影响，控制题材与时间 |
| **交错分批** | 同一改动分批上线，中间留间隔 | ≥ 2 批 × 5 条 | 排除大盘/节假日等时间因素 |

### 实例：检验"16 期节奏改革见效"

原文结论：「16 期节奏改革在视频号同样见效，均播 41.33s 全场第一……抖音侧结论在视频号侧独立复现」。

这个结论有三重混淆：

| 混淆源 | 说明 |
|---|---|
| ① 因素未分离 | 16 期同时具备「新节奏 + 词源题材」，无法判断是节奏还是题材的功劳 |
| ② 时间因素 | 08-29 当日账号总播放 1,712 为全周最高，可能是大盘波动，而非该条更强 |
| ③ n = 1 | 单条样本无法做任何统计推断，只能算轶事 |

**验证方案（进决策台账，4 周回收）**：

```
设计：单变量轮换，固定题材为词源
  臂 A（对照组）：词源 + 旧节奏        → 目标 n = 6 条
  臂 B（实验组）：词源 + 16 期新节奏    → 目标 n = 6 条
  交错分批：两周一批，避免同期货大盘影响
  主要指标：D7 播放中位数
  次要指标：完播率、均播时长
  判定：两组 Bootstrap 95% CI 不重叠 且 差异方向稳定 ≥ 2 批 → 升为结论级
  回收日期：4 周后（约 2026-09-30）
```

**当前应写的表述**：「16 期表现优异（D1 播放 1,680、均播 41.33s 为本期最高），但节奏改革的因果尚未验证（**n=1，且题材与时间因素混淆**）。已启动单变量轮换实验，4 周后判定。在此之前，新节奏可作为默认模板使用（**风险低、 upside 明确**），但不宣称已验证。」

## 方法五、基线建模与预测

### 5.1 D1 → D7 预测

快照体系建立后，用长尾系数 K 的中位数预测：

```
预期 D7 播放 = 实测 D1 播放 × K̂
K̂ = 该题材（样本不足时用账号整体）的 K 中位数
预测区间 = [D1 × K 的 25 分位, D1 × K 的 75 分位]
```

价值：新片发布 1 天后即可预估终值，**把决策提前 6 天**——决定要不要给这条内容投流、要不要立刻追拍同系列。

### 5.2 选题评分卡（周复盘 Q3 的产出工具）

```
预期 D7 播放 = 题材基线中位数 × f(标题句式) × f(节奏) × f(平台)
```

| 系数 | 初值 | 校准方式 |
|---|---|---|
| 题材基线 | 该题材 D7 播放中位数 | 每 4 周重算 |
| f(标题句式) | 1.00 | 由标题专题的配对实验给出 |
| f(节奏) | 1.00 | 由节奏专题的轮换实验给出 |
| f(平台) | 视频号/抖音分别计算 | 每 4 周重算 |

**纪律**：系数未经验证前一律取 1.00，不得凭感觉调。输出必须是**区间**（Bootstrap 分位），不是点值。

### 5.3 目标设定（周复盘 Q1 用）

- 冷启动期（当前）：目标由用户直接给定；
- 积累 8 周后：自动目标 = 近 8 周中位数 × (1 + 近期趋势斜率)，分析师审核后可覆盖；
- **pacing 检查**：周中可据已完成条数 × 单条基线，外推周末预期值，提前预警缺口。

## 方法六、决策量化（建议三件套）

### 规则
**没有三件套的建议，不写进报告。** 这是把报告从"建议清单"变成"决策依据"的关键一跃。

### 三件套

| 要素 | 要求 | 反例 |
|---|---|---|
| **预期影响** | 给出量化区间与口径，如「周播放 +8%~+15%」 | "显著提升" |
| **验证指标** | 明确指标名 + 判定标准 + 样本要求 | "看效果" |
| **回收日期** | 具体到日期，进决策台账 | "持续观察" |

### 改写实例

**原文建议**（08-31 周复盘第 1 条）：
> 「视频号继续加码词源冷知识：完播 Top3 全词源、播放前二全词源、分享前二全词源（事实）」

**改写后**：
> **建议**：下周视频号 8 条中，词源题材从 5 条增至 6 条（+1 条），雅称保持 2 条不变（不停做，继续积累样本）。
> **预期影响**：按本期分解结论（效率贡献 70%），若词源 D7 播放中位数维持 1,000+，周播放预计 **+8% ~ +14%**（Bootstrap 95% CI，基于词源 n=3，**区间不稳定，仅供参考**）。
> **验证指标**：① 下周词源条 D7 播放中位数 ≥ 800；② 词源组累计 n 达 6（向 n≥8 推进）。
> **回收日期**：2026-09-07（下期周复盘）。
> **置信度：低**（n=3）——本建议属于"低风险执行 + 持续取证"，不作为规范确立。

### 建议的四种类型（标注清楚，避免误读）

| 类型 | 含义 | 处置 |
|---|---|---|
| **执行** | 证据充分，直接做 | 进排期 |
| **试做** | 证据不足但风险低，做了能取证 | 做，同时登记验证方案 |
| **暂缓** | 证据不足且成本高 | 进观察队列，不占用产能 |
| **护栏** | 合规/质量底线 | 无条件执行，不做收益权衡 |

## 方法七、内容生命周期追踪（2026-09-02 新增）

### 用途

回答一个被长期默认、却从未验证的问题：**内容发布后还能涨多久？**

这个问题的答案决定了：
- 长尾系数 K 是否是一个有意义的指标（若内容 D3 后不涨，K 恒等于 1，该指标应废弃）；
- 增长该靠"发布密度"还是"长尾复利"；
- 同熟度对比中，M≥几 的作品才可以互相比较。

### 做法

利用**两次快照的重叠作品**（标题匹配 + 成熟度），追踪同一条内容在两次快照间的增量：

| 步骤 | 操作 |
|---|---|
| 1 | 取本期与上期快照，按标题归一化（去空白后前 12 字）匹配同一条内容 |
| 2 | 计算每条的期间增长率 =（本期播放 − 上期播放）÷ 上期播放 |
| 3 | 按**当前成熟度 M 分组**：M≥3 组 vs M<3 组，分别取增长率中位数 |
| 4 | 判定：若 M≥3 组增长率中位数 **< 2%**，则认定"内容已见顶，无长尾" |

> 巧妙之处：这份数据本来是"增长分解的干扰项"（批次重叠导致分解失效），但换个问法，重叠恰恰提供了**同一批作品的两次观测**，是追踪生命周期的天然素材。

### 实例：本账号实测（2026-08-28 → 08-29，间隔 1 天）

| 平台 | M≥3 组（n=3） | M<3 组（n=4） | 判定 |
|---|---|---|---|
| 视频号 | **+0.94%** | +7.64% | 已见顶 |
| 抖音 | **+0.33%** | +1.84% | 已见顶 |

逐条数据（视频号）：「4 句话」1,464→1,477（+13）、「国宝」883→897（+14）、「诗意外号」425→429（+4）、「皇帝改名」895→902（+7）、「文具」344→348（+4）。

## 六、脚本用法

```bash
# 1) 只跑数据质量门禁（导入后第一步）
node scripts/analytics/deep-metrics.mjs \
  --wechat="docs/数据分析/导入/视频号/260823-260829视频号动态数据明细.csv" \
  --asof=2026-08-29 --dq-only

# 2) 双平台完整分析（推荐：生命周期 + 分解 + 集中度 + 题材检验 + 跨平台配对）
node scripts/analytics/deep-metrics.mjs \
  --wechat="<视频号本期csv>"  --asof=2026-08-29 \
  --prev-wechat="<视频号上期csv>" --prev-asof=2026-08-28 \
  --douyin="<抖音本期csv>" \
  --prev-douyin="<抖音上期csv>" \
  --topics=scripts/analytics/topics.json --force \
  --out="docs/数据分析/体系/示例输出-YYYYMMDD-双平台深度分析.md"

# 3) 单平台 + 与上期对比
node scripts/analytics/deep-metrics.mjs \
  --wechat="<本期csv>" --asof=2026-09-05 \
  --prev-wechat="<上期csv>" --prev-asof=2026-08-29 \
  --topics=scripts/analytics/topics.json --out=out/deep-metrics.md
```

**参数说明**：
- `--prev-wechat` / `--prev-douyin`：**按平台指定上期文件**（必需，否则抖音会错用视频号的上期数据）；未指定时回落到通用 `--prev`。
- `--force`：门禁为 D 级时仍输出分析（**仅供内部预览判断"值不值得补数"，严禁粘入正式报告**）。
- `--aging='{"W1":3,"W2":2}'`：传入缺口连续缺欠周数，触发账龄惩罚（连续 ≥3 周额外 −10）。

**输出内容**（每个平台一节）：

| 节 | 内容 |
|---|---|
| ⓪ | **护栏检查**（零数字铁律等硬底线，门禁阻断时照样上报） |
| ① | 数据质量门禁表（评分 + 阻断项 + 警告项） |
| ② | 单条明细表（成熟度、派生比率、相对基线 R） |
| ③ | 同熟度排行（D1/D3/D7 分榜） |
| ④ | **内容生命周期追踪**（同作品跨快照增量 + 衰减判定） |
| ⑤ | 增长分解（含**批次重叠检查**，重叠时自动作废并提示改用集中度） |
| ⑥ | **播放集中度**（CV + Top2 占比 → 加更 vs 提质量） |
| ⑦ | 题材分组检验（Bootstrap CI + 置换检验 p 值） |
| ⑧ | 待补数据清单 |

**末尾追加**（仅当同时传入两个平台时）：**跨平台配对分析**——同内容、同成熟度的配对比较，符号检验 + 平台×题材交互效应。

**题材映射文件** `scripts/analytics/topics.json` 格式（期号关键词 → 题材）：

```json
{
  "词源冷知识": ["七月流火", "4句话", "国宝", "4个词"],
  "万物雅称": ["雅称", "诗意", "文具", "十二个月"],
  "科举": ["连中三元", "独占鳌头"],
  "避讳": ["皇帝改名"]
}
```

未命中任何关键词的作品归入「未分类」，**不参与分组检验**（避免硬猜）。
