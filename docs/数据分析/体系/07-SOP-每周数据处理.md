# 每周数据处理 SOP（双平台运营数据 · 片刻中华）

> 触发时机：用户说「数据导好了」「放在导入目录了」「做周复盘」，或每周一例行。
> 你的角色：数据分析执行人。用户只负责从平台后台导出文件，其余全部由你完成。

## 〇、开工前必读的硬规矩（违反任何一条都会产出错误结论）

1. **两平台数据严格不混算**：抖音与视频号的均值、基线、比率分别计算；跨平台对比单独成篇并标注口径差异。
2. **两种颗粒度不得混算**：`作品明细` = 一条视频一行（累计值）；`每日聚合` = 一天一行（当日增量）。
3. **JSON 文件名日期 = 剪片/建题库日 ≠ 发布日**。发布日通常比剪片日晚 0~1 天。期号识别只做「发布日 ≥ 剪片日」软校验，**不得**用「发布日 ≈ JSON 日期」硬判定。
4. **同一视频两平台同一时间发布**。视频号 CSV 无发布时间列时，用抖音 xlsx 同日期同内容的发布时间回填；抖音未发的视频号独发内容留「—」。
5. **识别不出的视频绝不猜测**，列入「未识别清单」请用户确认。
6. **文件保护**：`docs/发布台账.md` 绝不能删（期号映射主干）；`docs/数据分析/_归档/` 只读不分析，不作为当期依据。
7. **中位数优先于均值**：单条层面一律用中位数（爆款会拉高均值 20%+）。
8. **成熟度口径**：M = 快照日 − 发布日（天）。M<7 的作品数据未定型，跨成熟度不得直接比较数值。

## 一、第 1 步：导入文件整理（自动改名 + 归位）

用户每周一 09:00 从平台后台导出 4 个文件，**直接放进 `docs/数据分析/导入/`（根目录或任意子目录、名字随意）**，无需手动改名。

AI 接手后先跑：

```bash
python3 scripts/extract-dashboard-data.py --organize
```

自动完成：
- **识别**：文件名关键词优先（平台原始导出文件名：`视频号视频详情数据`=视频号作品明细、`视频号动态数据明细`=视频号每日聚合、`作品列表导出`=抖音作品明细、`数据表现_短视频全量指标`=抖音每日聚合），判不了再读表头内容兜底；
- **改名归位**：`平台-导出日-颗粒度-数据窗口.ext`，移到 `导入/{平台}/{颗粒度}/` 子目录；
- **导出日**：取文件导入时间（mtime）；若早于数据截止日，按数据截止日取并在报告中注明；
- **不动的情况**（报告中列出，请用户确认）：已合规文件直接跳过；目标同名已存在；表头/日期无法识别。

整理后的目录布局：

```
docs/数据分析/导入/
├── 抖音/作品明细/     ← xlsx，一条视频一行
├── 抖音/每日聚合/     ← xlsx，一天一行
├── 视频号/作品明细/   ← csv（utf-8-sig）
└── 视频号/每日聚合/   ← csv（前两行是标题+免责声明，第三行才是表头）
```

- 导出窗口应为「上周日往前 30 天」，起点固定不滚动（防老视频掉出快照链）

## 二、第 2 步：数据质量门禁（不过不出报告）

逐项检查，结果写进复盘报告开头：

| 检查项 | 判定 |
|---|---|
| 每日聚合日期覆盖 | 与数据窗口比对，缺口是「发布空档」还是「数据缺失」（与发布台账交叉验证） |
| 作品明细重复行 | 应为 0 |
| 窗口外残留数据 | 应为 0 |
| 抖音投稿量勾稽 | 每日聚合的投稿量 vs 当日作品明细条数，差异需标注请用户确认 |
| 累计值 vs 当日增量 | 差异属口径差异（预期内），记录数值即可 |

**技术备忘**：
- 视频号 CSV 日期是 `2026/09/02` 斜杠格式，抖音 xlsx 是 `2026-09-02 18:00:00` 横杠格式，解析必须兼容两种
- 抖音 xlsx 由 `extract-dashboard-data.py` 内置的标准库读取（无需 openpyxl）；视频号 CSV 用 utf-8-sig 编码

## 三、第 3 步：台账登记 + 看板数据生成

```bash
# 0. macOS/Linux 无 Excel COM：先把抖音 xlsx 转成 UTF-8 CSV（Windows 可跳过此步）
python3 scripts/extract-dashboard-data.py --to-csv

# 1. 登记发布台账（Excel → 期号识别 → 更新 docs/发布台账.md）
node scripts/build-ledger.mjs --wechat=导入/视频号/作品明细/xxx.csv --douyin=out/抖音-YYYYMMDD-作品明细.csv

# 2. 生成看板数据 + 同步看板内嵌基线（打开 看板.html 即最新，免手动导入）
python3 scripts/extract-dashboard-data.py --sync-seed
```

- 台账识别不出的行会写入 `out/ledger-unmatched-*.txt` → 汇总成「未识别清单」请用户确认（哪些是纯内容视频无需对题、哪些需补录题库）
- 台账 dedup key = `日期|平台|期号`，同天同平台同期号多条视频会被合并，遇到需人工分别登记

## 四、第 4 步：周复盘报告

产出 `docs/数据分析/分析报告/对比-YYYYMMDD-双平台周复盘.md`（模板见 `体系/04-模板-周复盘.md`），要点：

1. **执行摘要**：双平台核心指标表（总播放/条均/互动/涨粉/完播率/近7天日均 vs 前21天）
2. **数据质量校验**结果（第 2 步产出）
3. **趋势分析**：近 7 天 vs 前 21 天日均对比，指出驱动系列
4. **爆款 TOP5**（双平台分列，标注成熟度 M）
5. **主题 × 表现**：按期号主题的中位数播放对比，样本 n<5 标「观察级」
6. **结论与建议**：每条标注【事实】/【推测】，事实=数据可见，推测=需验证
7. **待确认事项**：未识别视频、勾稽差异、题库待补项

**告警规则**（只监测不归因）：单条播放低于基线×0.5；点赞率低于基线×0.7；完播率连续 3 期下滑；周发布条数低于目标（6–8条/周/平台）80%。

## 五、第 5 步：交付给用户

用户每周只看 1 份文档 = 周复盘报告。交付时告知：
1. 复盘报告路径（核心结论摘要写在回复里）
2. 看板更新方式：直接打开 `docs/数据分析/看板.html` 即为最新（第 3 步 `--sync-seed` 已同步内嵌基线）；
   需要恢复历史快照或换设备时再用「导入新数据 / 导入恢复」
3. 需用户拍板的事项（未识别清单等）单独列出

## 六、每月第一个周一（加做月度复盘）

在周复盘基础上打通题库台账做「选题 × 表现」归因：
- 发布台账 → 选题归档.md → `src/data/questions-*.json`，取每条视频对应的题型/题量/主题
- 输出题型 × 平台矩阵、主题复利分析（同主题 8 期内不重复出题，见题库记录.md 约定）

## 七、口径速查（两平台字段对照）

| 本项目口径 | 抖音原始字段 | 视频号原始字段 |
|---|---|---|
| 播放量 | 播放量 | 播放量（明细=累计；日表"播放"=当天新增，不可相加） |
| 点赞 | 点赞量 | 喜欢 |
| 评论 | 评论量 | 评论量 |
| 转发 | 分享量 | 分享量（另有"转发聊天和朋友圈"列，口径不同不混用） |
| 收藏 | 收藏量 | 无此列 |
| 涨粉 | 粉丝增量 | 关注量 |
| 完播率 | 完播率（小数） | 完播率（百分比，两平台口径不同不可横比） |

## 八、给其他 AI 的使用说明

本 SOP 自包含，不依赖特定工具链：
- 有文件读写能力的 AI（Claude Code / Cursor / 桌面 Agent）：直接按步骤执行，路径相对项目根目录
- 无文件能力的 AI（网页对话）：把本周 4 个导出文件的内容粘贴给它，让它按第三~四步的口径做分析（跳过台账登记与看板）
- 运行环境：python3（仅标准库，无需 openpyxl）、node（跑 build-ledger.mjs 时需要；macOS/Linux 下抖音 xlsx 先经 `extract-dashboard-data.py --to-csv` 转 CSV 再传入）
