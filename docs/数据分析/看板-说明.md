# 数据看板使用说明

> 创建：2026-09-03 ｜ 对应工具：`docs/数据分析/看板.html`（本地单文件，无外部依赖）

## 是什么

一个本地打开即用的**双平台运营数据看板**，整合 `导入/` 下的 4 个数据文件与 `发布台账.md` 的期号映射，覆盖：

1. **本期关注**（置顶）：爬坡期作品（发布未满 7 天、成熟度 M<7，数据未定型）+ 周发布条数护栏告警
2. **双平台总览**：总播放 / 条均 / 互动 / 涨粉 / 完播率 / 近 7 天日均增幅（与前 21 天对比）
3. **每日播放趋势**：两平台当日增量折线图
4. **主题 × 平台表现**：按期号主题的中位数播放对比（遵循指标字典「中位数优先于均值」）
5. **作品表现明细**：可按平台 / 主题 / 是否识别期号筛选，点击表头排序，标注成熟度 M

内置 2026-09-03 导出的 30 天基线数据（抖音 50 条作品 + 28 天聚合，视频号 55 条 + 30 天），数字已与
`分析报告/对比-20260903-双平台30天基线.md` 对账一致。

## 每周一更新流程

1. 平台后台按惯例导出 4 个文件，放入 `导入/` 对应目录（命名规范见 `数据分析/README.md`）
2. 运行提取脚本（带 SEED 同步，看板打开即最新）：
   ```bash
   python3 scripts/extract-dashboard-data.py --sync-seed
   ```
   产出 `docs/数据分析/看板-data.json` 并同步 `看板.html` 内嵌基线
3. 直接打开 `看板.html` 即可看到最新数据；需要恢复历史快照或换设备时再用「导入新数据 / 导入恢复」

合并规则（与 README 一致）：同一条视频多份快照取导出日最新；同一导出日的快照直接覆盖。

## 数据安全

- 数据存浏览器 localStorage（键 `wb_video_dashboard_v1`），换设备前先「导出备份」再「导入恢复」
- 「恢复内置基线」可随时回到 2026-09-03 的预置数据（有二次确认）

## 口径更新（2026-09-03）

- **完播率 KPI 由均值改为中位数**（对齐指标字典「中位数优先于均值」）。与基线报告
  `分析报告/对比-20260903-双平台30天基线.md` 中的「完播率均值」口径不同，对账时注意区分。
- **成熟度 M 的口径改为「快照导出日 − 发布日期」**（此前用数据最大日期，差一天会影响 D7 边界判定）。
- **数据清洗规则**（提取脚本 `scripts/extract-dashboard-data.py` 内置）：
  - 视频号「平均播放时长」列形如 `32.35秒`，脚本自动去「秒」字解析；
  - 抖音播放为 0 的作品，留存类字段（完播率/5s/2s/均播时长）统一归零，防止脏值污染统计；
  - 每日汇总中互动类负值（如取消点赞）归零；
  - 提取脚本已改为纯标准库解析 xlsx，不再依赖 openpyxl。
- 总览卡片的「30 天」标签改为按实际数据窗口天数动态显示（抖音 28 天、视频号 30 天）。
