# 视频号中国文化口播产线评估

评估日期：2026-10-13。目标：输入抖音链接、本地视频或音频，完成原创文案、素材、MiniMax 配音与视频合成，并持续改善视频号表现。

本次检查了当前生产入口、文案与字幕规则、对话及 Hypit 产线、分析脚本、近期复盘和两个本地成片的抽帧。没有重新登录后台取数，没有完整回听全部作品，没有修改生产代码或调用付费生成接口。下列方案尚未实施。

## 一、判断与证据边界

项目已有较完整的出片零件，包括转写、配音增量缓存、音频实测时长、素材索引、多个合成器与数据分析工具。优先补强的是内容决策、跨产线质量验收、作品与运营数据的关联。

最近可用的数据来自 `out/账号近期数据复盘-20261011.md`：

- 视频号 10 月 6—11 日的 9 条作品，累计播放中位数 190；9 条评论均为零。
- 西安地名历史样本有 3,295 次播放、92 次转发、48 次推荐，值得作为重新测试的线索。
- 该快照缺少近期单条平均观看时长、留存曲线和流量来源；作品发布年龄也不同。不能由此证明地名一定更好、长片一定更差，或账号被限流。
- 9 月旧报告包含题目类作品，而且最新复盘声明撤回旧 CSV 的相关引用。本次不把旧答题结论直接套给当前口播，也不把抖音留存当作视频号证据。

## 二、优先级最高的内容改进

### 1. 从“改写原稿”升级为“重新设计这一期”

`script-rewriter` 已要求结构拆解、事实核查和逐句重写，这是可保留的基础。但其辅助脚本只是句长、词表等统计；这些统计不能判定观众是否想看。

在生成正文前，增加一张简短内容卡：

| 字段 | 要解决的问题 |
|---|---|
| 观众联系 | 为什么一个普通观众会对这件事在意？与家乡、日常语言、家庭记忆或现实困惑有什么联系？ |
| 核心问题 | 本期主要回答哪一个问题？ |
| 看完所得 | 能复述什么具体知识，或理解什么人物选择？ |
| 新角度 | 相比原视频新增什么理解、证据或叙述方式？ |
| 开场承诺 | 第一句承诺讲清什么？何时开始兑现？ |
| 事实来源 | 哪些是史料，哪些是传说、争议或艺术重现？ |

每次内部比较两个开头，选择一个主稿，不要求用户逐步审批。不要以“重复率低于某数值”替代原创判断，也不要默认保留参考片的长度和全部知识点。

### 2. 聚焦每条视频的承诺，保留题材自由

“中国文化”可以覆盖很多主题，但每条片最好有一个清晰承诺。建议先测试三类内容：地方名字与日常生活、熟悉词语或习俗的误解、历史人物的一次具体选择。它们是实验方向，不是已验证的赢家。

对人物故事，先尝试讲清一个事件，避免默认按出生、求学、成就、苦难、升华写完整小传。对成语串联，只在故事确实自然成立时使用“一生”结构，不让所有母题都迁就固定六条。

林徽因现有旁白到约 19.5 秒才讲完人物姓名，开头从外国大学和毕业典礼切入。这可以测试改为先点出人物与事件，再交代背景；不是断言当前开头必然无效。原稿中的具体数字、人物原话与现场细节仍需分别核验，不能因参考视频讲过就当作事实。

### 3. 让画面承担解释任务

镜头清单除了图片提示词，还应记录“对应哪句旁白、帮助观众看懂什么、素材从哪里来”。

- 地名来历：地图、位置变化、旧名与新名之间的关系。
- 文物建筑：真实对象、局部细节、对应史料。
- 人物选择：具体行动和处境，用示意画面辅助叙述。
- 史实证据优先使用可核验资料；生成画面承担情境重现，避免把生成照片、题字或证书当作史料。

现有林徽因镜头计划中，多张图持续十几秒甚至二十余秒。推拉本身不能保证增加信息；应按旁白的信息变化安排细节、地图或证据，而非机械规定每几秒切一次。先复用素材库，缺少解释性画面时再搜索或生成。

## 三、确定的工程改进

### P0：统一成片验收

实测与代码证据：

- `out/林徽因01-成片.mp4` 时长约 343.87 秒；抽取第 5 秒，字幕只显示一个“上”字。应检查断句是否把语义片段切碎，不能只验证最多 14 字。
- `out/林徽因01-成片-平滑版.mp4` 时长 332.10 秒；现有旁白 SRT 最后一条结束于 343.839 秒。两者差约 11.7 秒。对应脚本手写镜头时长并使用 `-shortest`，应回听确认是否截尾；尚未确认该版本是否发布。
- `scripts/story/compose-linhuiyin-01-smooth.py` 虽声明 SRT 路径，实际合成步骤没有使用它。文件名带“成片”不能作为字幕完整的保证。

每种合成器输出后，都应检查：音画及字幕总时长、最后一句是否完整、字幕时间是否越界、黑帧、异常静音、音频峰值、素材是否缺失。生成开场、中段、结尾及异常位置的预览供核对。单字字幕只告警，不一律禁止，因为释字内容可能有意单字展示。

### P1：字幕按真实语音对齐，规则变成公共配置

`scripts/dialogue/compose-video-motion.py:152` 起，将一句字幕拆成短句后，按字数比例分摊到下一句开始前。这包含句间停顿，不能准确代表每个词何时说出。

建议保留现有黄色单行、62% 高度等默认外观；用真实时间戳驱动字幕，按语义断句，再用 14 字上限兜底。必要时保留系列覆盖配置，避免各脚本复制常量后逐渐偏离。

MiniMax 当前官方同步接口支持 `subtitle_enable`、句级/词级 `subtitle_type` 和 `pronunciation_dict`。先在少量中文专名上验证返回结果及字幕与配音文本的映射，再接入产线。官方文档：https://platform.minimax.cn/docs/api-reference/speech-t2a-http 。

字幕文字与送 TTS 的读音处理分开保存。旧缓存缺少时间戳时，可以对已有音频做对齐，不应自动整库重新扣费合成。缓存键需包含所有影响音频的有效参数；字幕服务元数据也要单独保存。

### P1：统一入口和任务记录，继续复用各合成器

当前 `render:auto` 面向题库；口播存在 dialogue、story、Hypit 多条路径。建议增加统一任务入口，识别来源并选择适用产线，保存：

`来源 → 校正版转写 → 内容卡 → 事实依据 → 主稿 → 旁白 → 实测时间轴 → 素材与镜头 → 合成 → 验收 → 发布包`

每一步记录输入版本、产物、状态和成本；失败后从对应阶段恢复，改一句不重新生成所有素材。按期隔离临时目录，避免 `out/_mm_tts_tmp` 等共享目录在并行任务时相互覆盖。可以先产出开场小样做自动和人工抽检，再生成整片；用户正常输入来源即可，无需逐阶段操作。

发现两个应在接入统一入口前修正的契约问题：

- `scripts/rewriter/extract-script.py` 的视频分支把转写子进程的 stdout 当成正文；而 `scripts/utils/transcribe-ref.py` 把正文写进文件，stdout 主要是“写出路径”等日志。该分支可能分析日志，需读取真实转写文件并检查非空。
- Hypit 新建脚本写入的说明仍称镜头数不得超过句数，但对应 README 已明确更正。应按实际生成器行为统一文档与校验，避免每期开片重复踩坑。

### P1：让口播作品进入复盘系统

`scripts/analytics/build-ledger.mjs` 的自动索引当前只扫描 `src/data` 顶层的 `questions*.json`，没有直接纳入口播 JSON 和 Hypit productions。已具备分析工具，但新口播不容易自动关联回它的文案与镜头。

增加稳定作品 ID，关联平台作品 ID、最终文件、文案版本、选题类型、开头类型、时长、素材形式、发布时间。保留每次采集时间和发布后小时数，统一比较发布后 24 小时及 7 天的快照。读取不到的字段记为空，不能填零。

## 四、下一轮可执行实验

先做 6 条筛选样本：地方文化、词语或习俗、人物具体事件各 2 条。首轮统一一个接近的时长区间，例如 60—90 秒，并尽量保持音色、画面质量和发布时间段相近，交错发布。这个区间只是控制变量的起点，不是视频号最佳时长结论。

首轮每类只有 2 条，结果只用于挑选后续测试方向，不足以给题材定输赢。第二轮再围绕表现较好的方向，用新内容成对测试“先给答案”与“先提问题”等单一变量；不把同一片简单换头重复发布当成严格 A/B 实验。

每条同时记录播放、平均观看秒数、完播率、分享数、分享/千次播放、关注数、关注/千次播放，以及后台实际提供的流量来源。低播放时必须同时展示原始计数，避免一两次分享造成比率看似大涨。不同片长不只比较完播率。

复盘输出应落到下一期动作：哪些开头继续测、哪类铺垫删掉、哪种画面确实帮助理解、哪些题材值得投入。没有相应观看或来源数据时，只列假设，不输出“被限流”或“某格式必爆”的结论。

建议实施顺序：先修输入契约和成片验收，再补作品记录与数据关联，同时开展小批内容测试；最后根据结果扩展模板和素材投入。
