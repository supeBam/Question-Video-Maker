# 项目文件保护清单

> 维护人：后勤（项目架构与文件管理） ｜ 版本：v1.0 ｜ 2026-08-27
>
> **依据**：用户要求建立「哪些文件不可以随便删除」的保护规则，避免误删造成灾难后果。
>
> **配套文档**：文件分类与命名见 [`项目文件分类规范.md`](项目文件分类规范.md)；本文档与分类规范互链，冲突时**以本文档为准**（宁可不删，不可错删）。
>
> **生效范围**：全体成员（内容选题 / 内容创作 / 内容审核 / 数据分析 / 后勤）。违反本清单的删除 / 移动视为事故，须第一时间向船长报告并恢复。

---

## 一、防误删总规则

1. **先列清单、后动手**：任何成员要删除或移动本清单第二、三节所列文件，必须先把「文件路径 + 理由 + 目标位置」列成清单报船长，船长批准后由后勤执行。
2. **git 可恢复 ≠ 可随意删**：工作区可能有他人在用、仓库历史会乱、恢复有成本（尤其二进制素材与 `.agent-teams/` 团队状态）；恢复能力不是删除许可。
3. **每次审计先对照本清单**：后勤做整洁度审计时，先比对保护清单，再输出清理建议；不在清单里的文件默认按「需批准」处理。
4. **执行走 git**：删除 / 移动一律用 `git rm` / `git mv`（保留历史可追溯），禁止绕过 git 直接删文件。
5. **疑问即停**：不确定文件是否受保护时，默认按「受保护」处理，先问后勤 / 船长，不要赌。

## 二、【绝对禁止删除 / 移动】清单

除非船长与用户明确同意（且由后勤执行），下列文件 / 目录一律禁止删除、移动、改名、覆盖：

| 类别 | 路径 | 保护原因 |
|---|---|---|
| 题库 | `src/data/` 全部题库 JSON（`questions-*.json`） | 每一期唯一内容资产；三个固定文件（`questions.json`、`questions-crossword-demo.json`、`questions-wanwu-yacheng.json`）被 `src/Root.tsx` 直接引用；`questions-back.json` 是第 5 期唯一存档 |
| 查重登记 | `题库记录.md`（根目录） | 出题查重唯一依据，丢失即可能重复出题 |
| 规范与报告 | `docs/` 全部规范文档（`项目文档.md`、`项目结构.md`、`项目文件分类规范.md`、本文档、`审核基准.md`、`选题数据-抖音视频号.md`、`选题归档.md`） | 团队协作与合规依据 |
| 报告与数据 | `docs/审核报告/`、`docs/数据分析/`（含导入 / 原始数据 / 分析报告） | 运营合规与数据复盘资产，不可再生 |
| 素材 | `public/assets/` 全部（`*.svg` 背景、`audio/` 音效、`bg-audio/` BGM、`doc/` 参考资料、`tts/` 配音） | 渲染直接引用，删除即坏片 |
| 技能 | `.agents/skills/` 全部（`generating-quiz-json/`、`team-operations/`） | 出题 / 协作流程依赖 |
| 工程配置 | `package.json`、`README.md`、`AGENTS.md`、`.gitignore` | 构建 / 依赖 / 协作约定基础 |
| 团队状态 | `.agent-teams/` | 团队任务与消息状态，仅由 agent_teams_* 工具维护，禁止手工改动 |
| 版本库 | `.git/` | 删除即失去全部历史，灾难级 |

## 三、【需船长批准才能动】清单

以下文件重要但必要时可调整；任何**移动 / 改名 / 覆盖 / 删除**都须先列清单报船长批准：

| 类别 | 路径 | 说明 |
|---|---|---|
| 根目录配置 | `tsconfig.json`、`remotion.config.ts`、`.gitignore` | 构建与渲染配置 |
| 特殊题库 | `questions-back.json`（移动 / 改名需批准；删除仍属第二节禁止） | 第 5 期唯一存档，改名会破坏 `选题归档.md` 记录与 git 历史 |
| 源码 | `src/*.ts`、`src/*.tsx`、`src/components/`、`src/scenes/`（`src/data/` 之外） | 渲染逻辑 |
| 脚本 | `scripts/*.mjs` | 出片 / 校验流程 |
| 测试 | `tests/*.test.mjs` | 回归保障 |
| 早期文档 | `STORYBOARD.md`、`overview.md`、`ref-package.json`、`README.md` 的内容改写 | 后三者涉及 9 项待裁决事项，裁决前维持现状 |
| 技能锁 | `skills-lock.json` | 与 listenhub-voice 技能去留联动，待船长裁决 |
| 工具状态 | `.dsh/`、`.listenhub/` | harness / 工具状态目录（是否 gitignore 待裁决） |

## 四、【可安全清理】清单

以下无需船长批准即可清理，但须满足三条前提：① 不清理他人正在使用的产物；② 不清理当日刚渲染、正在发布的成片；③ 清理前确认无未提交改动依赖它们。

| 路径 | 内容 |
|---|---|
| `out/` | 全部渲染产物（`.mp4` / `.png` / `.srt` / `.txt`）、`stills/` 截帧、临时草稿（已被 gitignore） |
| `node_modules/` | 依赖包，可 `npm install` 重装 |
| 临时文件 | 日志 `*.log`、一次性脚本、错放位置的草稿（先归位或报批，不直接删） |
| 缓存 | `.cache/`、`__pycache__/`、`*.tsbuildinfo` 等 |

## 五、审计对照流程（后勤每次执行）

1. 先读本清单与 `docs/项目文件分类规范.md`；
2. 盘点中发现的疑似冗余 / 散落文件，先判断属于第几节；
3. 属第二、三节的：只列入报告待船长裁决，**绝不擅动**；
4. 属第四节的：可建议清理；成片类产物确认无人在用后再执行；
5. 清理后在本清单末尾「变更记录」登记一笔（日期 + 内容 + 批准人）。
