## 三、命名规范

### 3.1 题库（`src/data/`）

- **常规**：`questions-YYMMDD-N.json` —— `YYMMDD`＝创作日期，`N`＝当天序号（当天第一期 `-1`，第二期 `-2`……）。
- **当天唯一一期**：可省略序号（现状：`questions-260813.json` 等 6 个文件无后缀）。建议统一口径为「唯一一期可不写 `-1`」，已出文件不改名。
- **铁律**：只新增、不覆盖历史文件；`N` 取当天未用的最小号；覆盖 `questions.json` 必须显式确认。
- **固定特殊文件（被 `src/Root.tsx` 引用或历史约定，不得改名）**：
  | 文件 | 含义 |
  |---|---|
  | `questions.json` | 当前活跃题库（`LiteratureQuiz` 合成默认数据源） |
  | `questions-crossword-demo.json` | 诗词填字示例（`CrosswordQuiz` 合成） |
  | `questions-wanwu-yacheng.json` | 万物雅称专题（`WanwuYacheng` 合成） |
  | `questions-back.json` | 第 5 期唯一存档（仅此一份，禁止再堆备份文件） |
- **出题后同步两处**：`docs/选题归档.md` 选题索引 + `题库记录.md` 查重登记。

### 3.2 数据文件（Excel / CSV / YAML）

- 用户导入 Excel：`YYYYMMDD-平台-内容.xlsx`，如 `20260827-抖音-作品数据.xlsx`；同一天多份用 `-2`/`-3` 区分。
- 历史冻结原始数据：`YYYYMMDD-来源-内容.yaml`（现状即此格式，冻结不再新增）。
- 存量 CSV 导出（`src/result/` 下）为遗留格式，新导出数据一律进 `docs/数据分析/导入/`（见 §六 问题 4）。

### 3.3 分析报告 / 审核报告

- 分析报告：`docs/数据分析/分析报告/平台-YYYYMMDD-主题.md`，如 `抖音-20260827-周复盘.md`；双平台对比 `对比-YYYYMMDD-主题.md`。
  > 现状遗留：`20260827-第一期账号复盘.md`、`20260827-核心指标分析框架.md` 未带平台前缀（见 §六 问题 5），新报告一律按平台前缀命名。
- 审核报告：`docs/审核报告/YYYYMMDD-主题.md`，如 `20260827-万物雅称第4期.md`（现状即此格式）。

### 3.4 发布物（`out/`，gitignored）

- 视频 / 封面 / 字幕 / 发布文案同前缀：`literature-quiz-epNN.mp4` + `.png` + `.srt` + `.txt`（文案单个 txt 内含「视频号 / 抖音」两段）；新期建议带期号命名（如 `成语-第01期.mp4`）。
- 封面截帧调试：`out/stills/`。
- **清理周期（每周复盘时执行）**：`out/` 是可再生产物目录，唯一源头是 `src/data/` 题库（受保护）。
  - **必清（可再生的调试垃圾）**：`burst-preview-*`、`burst-choice-*`、`check-*` 截图、`.remotion-props-*.json` 残留、`stills/` 内容——用 `node scripts/weekly-review.mjs` 一键清理。
  - **保留**：成套成片（`*.mp4` 及其同前缀 `.png/.srt/.txt`，已发布且无需留档时可人工删除）、`ledger-unmatched-*.txt`（未识别清单，确认处理后再删）。
  - **不删未知文件**：清理脚本无法归类的一律保留并提示。

### 3.5 音视频资源（`public/assets/`）

- 音效：`audio/`；BGM：`bg-audio/`；TTS：`tts/{series}-{episodeLabel}/{questionId}-{question|answer|punchline}.mp3`（由 `src/questionVoiceTracks.ts` 推导，勿手改路径）。
- 背景/装饰：`assets/*.svg`。

### 3.6 文档（`docs/`）

- 板块类文档直接放 `docs/` 根（审核基准.md、选题数据-*.md、选题归档.md、项目*.md）。
- 按主题开子目录：`审核报告/`、`数据分析/`、`superpowers/`；新增板块先报船长再建目录。
- 文档统一中文；日期一律 `YYYY-MM-DD`（文件名内 `YYYYMMDD`）。

## 五、整洁度规则（禁止事项）

1. **根目录零散落**：业务文档、数据、草稿、脚本一律不进根目录。
2. **备份文件不堆积**：题库备份仅限约定的 `questions-back.json` 一份；其他备份、`*-copy`、`*-old`、`*.bak` 一律不落盘。
3. **临时文件即用即清**：一次性脚本、临时 JSON、调试产物用完删除；确需保留放 `out/`。
4. **数据平台严格分区**：抖音 / 视频号数据分目录放、不混算（详见 `docs/数据分析/README.md`）。
5. **移动 / 删除先报批**：任何移动、重命名、删除存量文件，先对照 [`项目文件保护清单.md`](项目文件保护清单.md) 判断保护级别（禁止 / 需批准 / 可清理），再列清单报船长批准，后勤执行；成员不得擅自处理他人产出。
6. **新文件命名先查表**：见 §四；不确定时问后勤。
7. **不外链重文件**：音视频等二进制大文件只进 `public/assets/` 或 `out/`，不入 `docs/`。

## 七、与既有文档的关系

- **本文档**只管「分类 + 命名」；技术细节看 `项目结构.md`（其 §八 资源目录约定、§九 临时文件约定与本文档一致，冲突时以本文档为准，后续由后勤统一）。
- 删除 / 移动的允许范围见 [`项目文件保护清单.md`](项目文件保护清单.md)：两文档互链，冲突时**保护清单优先**（宁可不删，不可错删）。
- 板块内部约定由板块负责人维护：数据分析见 `docs/数据分析/README.md`，审核依据见 `docs/审核基准.md`，选题见 `docs/选题数据-抖音视频号.md` + `docs/选题归档.md`。
- 新文档创建后：若属新板块，须在本规范 §一/§二 登记并同步 `docs/项目文档.md` §十一 索引。
